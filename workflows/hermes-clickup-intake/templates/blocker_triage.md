Question-card triage (integration rules; a `CLICKUP-BLOCKER v1` relay names each question card, the work card that waits on it, its run and the worker's question). Answer each blocker id exactly once with one output comment whose first line is:
- `CLICKUP-OUT v1 kind=business_questions relay=${ref} blocker=<ids>` for a missing business or product decision;
- `CLICKUP-OUT v1 kind=technical_questions relay=${ref} blocker=<ids> boundary=none|security` for a technical, access, credential-provisioning or authorization decision that only a human can make. Use `boundary=security` when the worker stopped at a security, containment, safety or authority boundary. A missing or invalid boundary is recorded as security;
- `CLICKUP-OUT v1 kind=blocker_internal relay=${ref} blocker=<id>` when existing approved authority already resolves it, or it is an operator or infrastructure action. A boundary stop is not internal merely because it is a stop.
The question text states which step is blocked (in plain words), why human input is required, the real options and their consequences, and what happens after an answer. For a boundary question it also states that the boundary stays in force and that granting new authority requires a plan revision and new approval. It never contains secrets, tokens, raw logs or traces, file paths, hostnames, IP addresses, private URLs or other customers' data. The worker's question is Kanban-internal: never quote it to ClickUp.
You may `kanban_show` the work card; make no other card writes. Then park with `kanban_schedule(reason="CLICKUP_WAIT")`.
When an input relay lists "blockers needing a resolution for this generation", classify the generation as usual and, for each listed blocker, output either one comment whose first line is `CLICKUP-OUT v1 kind=resolution blocker=<id> relay=<relay_ref> gen=<g> authority=unchanged` followed by the decision for the worker, the cited ClickUp comment ids and a statement that no security or containment control is waived (at most 1,600 characters, same text rules as a question), or, if the answer is insufficient, a new question for that blocker; never repeat an unchanged question. A resolution never grants new authority: a ClickUp change that does is `material`.
When a later plan revision fully settles a blocker whose resolution generation was classified `material`, add to that revision's plan file one line per settled blocker, exactly `CLICKUP-INCORPORATES v1 blocker=<id> question=<question card> card=<work card> gen=<that resolution's gen>` on its own line without formatting. After the revision is approved and its orchestration finishes, the integration answers that question itself, bound to the approved revision; a later answer still goes through normal triage. Omit the line when the revision does not settle that decision; the question then stays with a human. Never complete a question card yourself.
