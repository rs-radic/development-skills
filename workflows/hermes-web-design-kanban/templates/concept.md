# Concept / revision handoff

Fill privately; these placeholders neither configure an integration nor grant authority. Follow the [workflow](../README.md) and [skill](../skills/concept-first-web-design/SKILL.md).

- Board/list, same tracker task and linked native card references: `<verified-bindings>`.
- Canonical project context and authority (readable by every worker): `<paths-and-binding-evidence>`.
- Original request / tagged revision request, actual platform author, current scope and acceptance criteria: `<source-references>`.
- Implementor, independent SPEC and quality/security profiles, integrator and independent E2E profile: `<verified-role-bindings>`.
- Concept approver set, separately configured release set, designated approval surface: `<private-identity-bindings>`.
- Current completed revision, source SHA and artifact identity: `<revision>`.
- Fresh remote DEV observation, fetched SHA, initial worktree HEAD and accepted prerequisites: `<baseline-evidence>`.
- Stable preview URL, isolated files/routing/assets/redirects/cookies/state, approved access boundary: `<preview-bindings-and-checks>`.
- Existing DEV settings/toolchain/deployment contract and protected borrowed resources: `<approved-boundaries>`.
- Exact owned worktree/ref/preview/runtime/cache allocation and prior cleanup registration: `<ownership-reference>`.
- Separately authorized effects, otherwise no-write/no-send restrictions: `<effect-boundaries>`.
- Relevant TDD, UI/browser/visual-QA and project-invariant skills, actual consumer-readable paths: `<required-reads>`.
- Checks run, evidence and outstanding failures: `<results>`.

Iterate in `concept` on this same task and stable preview. Any list member may propose or tag a revision; unaddressed discussion alone does not spawn work. Do not add a human plan-approval gate. Protect other concepts and shared services.

Before leaving `concept`, obtain one eligible concept approval for the current **completed** revision. Record actual platform author, explicit action, revision and freshness separately from technical checks. Freeze that revision for independent native same-card SPEC, then separate quality/security review. Concept approval is not release approval. Changed requests/code invalidate affected approvals and checks; reuse this task and existing linked cards.
